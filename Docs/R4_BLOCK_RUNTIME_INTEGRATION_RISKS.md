# R4 shape integration: current runtime boundaries

Read-only review of branch based on #999. These are integration requirements, not claims that shaped blocks already work.

The #963 source catalog references 30 collider GLB files. All 30 are present in the local source archive and their SHA-256 values match that archive's `SHA256SUMS.txt` (checked without Unity). The current Unity `Packages/manifest.json` does not list a GLB/glTF importer. These source files are references, not imported or validated runtime colliders; their hash match does not prove convexity, correct axis/scale, or faithful gameplay collisions. The visual FBX files already in the project do not resolve this physical-geometry gap by themselves.

The lightweight `Tools/R4Blocks/Test-R4ColliderStructure.ps1` check passed the GLB container and declared mesh/accessor structure for 30/30 files. They contain 36 mesh nodes; five shapes require multiple source collider meshes: Arch (3), Step (2), CoveEdge (2), CornerL3 (2) and Tee4 (2). The largest declared single mesh has 144 triangles. These counts are metadata checks only and do not themselves establish geometry or Unity physics behavior.

An additional offline numerical preflight (`test-collider-geometry.js` and `verify-collider-geometry.js`) passed 36/36 source meshes for finite vertices, nondegenerate triangles, paired consistently oriented edges, triangle-plane half-space convexity and a coarse axis-aligned envelope of the declared occupied cells, using the tolerances documented in `Tools/R4Blocks/README.md`. Synthetic open, degenerate, reversed, invalid-index, dented and outside-envelope examples were rejected. The bounding envelope cannot detect a collider occupying an empty corner of a nonrectangular footprint. This is not a Unity physics test, a proof of cooked collider fidelity or a check that a collider matches its visual mesh and allowed mounting patches.

1. `R3VehicleModel.OccupiedCells` currently returns only the anchor; `UsesWideFootprint` always returns false. A shape must resolve its own local cells, rotate each about the anchor and preserve a single part ID/HP. All occupancy consumers, including placement bounds and the 180-cell cap, need the same result. Missing shape information in a legacy save must resolve to the existing cube; an unknown nonempty shape must fail closed rather than silently becoming a cube.
2. `R3BuildValidation.Definition` caches by `Kind/ContactMask`. Different armor shapes with the same mask would collide in that cache. Any implementation that feeds catalog sockets into BUILD001 must key the cache by shape and every field that changes the definition, and verify that candidate preview, purchase, owned-item mount and repair/restoration all receive the same shape.
3. The existing `R3MountingGrid.Compatible` tests only a six-face mask. The P12 structure graph uses `R3BlockMountPoints.WorldMask` for every occupied cell; it does not encode per-cell patch offsets or partial-port area. Merely changing the garage placement gate would therefore let the runtime connectivity/destruction graph disagree with placement. Per-cell socket contact and declared internal bonds need a shared authoritative interpretation. Source-declared bonds still require collider/geometry verification.
4. `BuildSocketGeometry.Touches` checks socket kind and overlap area but does not know the staged catalog's `PartialSocket` or `MountModules` flags. `R4BlockCatalog.CanMountModule` is not used by actual placement. Enforce the full-port requirement in the real placement and restoration paths for weapons and mobility devices, including cases with multiple potential supports, without preventing legal structural connections through partial ports.
5. `R3PartState.Copy` and `R3ModelCheckpoint` copy individual parts, while the legacy-migration helper `ReachableCheckpointParts` indexes only anchors. Do not reuse that helper as a general multi-cell connectivity algorithm without adapting it. Verify identity, shape, orientation, HP, inventory and undo/restore through actual save/load; preserve existing legacy migration behavior.
6. `R3GarageView.CreateGhost`, physical assembly and `R3BuildValidation.CreateProbe` currently construct the old primitives independently. Visual preview, actual collider, repair probe and overlap checks must use the same shape and orientation; a model alone is not collision proof. Catalog grouping in the garage must distinguish shapes while still stacking individual parts of the same shape.

Minimum acceptance examples: a rotated two-cell piece remains one damageable object; a full-face contact permits a valid wheel or gun; a partial patch can connect compatible armor but cannot support a wheel, gun or movement module; an item with another valid full support remains installable; destroying a bridge detaches the same pieces in the P12 runtime graph and after load; old saves round-trip without gaining or losing parts. Cover the same policy in purchase, owned-item mounting, repair and restoration before exposing shapes in the UI.
