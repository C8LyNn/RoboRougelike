## Exact collection protocol
Run actual CHL scene in licensed disposable Unity6000.3.14f1 and use SAME fixed-timestep (50Hz), reference scene/source SHA, start/finish geometry, recording tool/input protocol and no cheats for all trials. Collect 3 **independently restarted real physical** complete attempts per rig (6 total). Retain unaltered `CHL003_ACTUAL_TRIAL_SUMMARY_CSV` log entries and full original events CSV, Unity Test XML/process exit, video or raw telemetry, source SHA and input record. Trials can have absolute numbering e.g. Light 2/3/4; the validator requires unique attempt IDs **not** 1/2/3. If no native result, use provided **header-only** W17_native_trials_EMPTY.csv and expect `NOT_RUN`. Never add invented rows to claim physical PASS.

**Executable read-only data acceptance:**
`node Docs/B01Design/CHL003_W16/W17_trial_scorecard.mjs /path/to/original_six_trial_summary.csv`.
Canonical columns are checked byte-for-byte (no variable schema), six unique entries and three of each profile, finite/nonnegative physical numbers, stable per-rig mass and width. **Every trial** must have Completed state, 4/4 ordered checkpoints, exactly one completion, zero falls, >35m physically traveled, >4 physics samples and nonzero physical ramp+bridge contact points. Failure returns `DESIGN_ACCEPTANCE_FAIL`, corrupt/partial data `INVALID_INPUT`; header-only `NOT_RUN`. Raw CSV by itself always returns `DATA_READY_NATIVE_EVIDENCE_PENDING` and **G2 HOLD**, never Unity/G1 PASS.

**Dynamic differentiation (NOT simple mass/width difference):** for each of elapsed seconds, peak speed and contact point density per travel meter at ramp, bridge and barrier, record all three raw values, min/max/median and within-rig spread. A candidate *repeatable* difference is identified ONLY if profile intervals do not overlap **and** inter-profile median gap exceeds the larger within-profile range. If no measured dynamic metric meets this, report `INCONCLUSIVE_NO_STABLE_DIFFERENCE` (NOT a balancing fail proven by only 3 trials). Additional operator evidence for acceleration, controllability and slips is needed to attribute cause. Any raw timing advantage is descriptive, **not** a prescribed outcome or automatic tuning directive.

## W17 traction / airborne game-design decision
**Proposed baseline: zero physically grounded driving wheels => ZERO drive propulsion and ZERO ground steering torque.** Falling / airborne state should preserve gravity and existing momentum; do not generate arcade midair push on input unless a separately specified/approved jump-jet or air-control module exists. Merely touching a barrier with the Core or body **must not** count as wheel-ground traction. For at least one grounded valid drive wheel, movement may be active, subject to actual Unity contact implementation/physics tuning. Do not make unapproved claims about wheel friction coefficients, differential torque or 50%-per-wheel scaling.

**Producer acceptance executable native cases** (B01-20 owns all runtime):
1. Four wheel/ground contacts: holding throttle from rest yields a **measured forward velocity change** with nonzero motor force; both rigs can drive ramps and bridge.
2. All four wheels separated from ground in an unobstructed fall: identical initial pose/velocity with throttle=+1 versus throttle=0, for **10 FixedUpdate steps @ 0.02s**: no non-gravity horizontal velocity difference due to motor, no steering-induced yaw difference. Gravity/fall proceeds. Avoid environment collisions and drag confounders. This is a **counterfactual** controlled test.
3. Core/chassis brushing a wall during airborne fall, wheels all not grounded: **still no drive traction**. A wheel touching a true drivable ramp must count only if actual wheel collider contact is confirmed (not trigger or art).
4. Re-ground after jump/fall if still in Running state: throttle resumes without cached extra impulses; Retry clears force/grounded state. Hold same steps for Light/Heavy.
5. Each of 6 full physical course trials must show at least one actual ramp and bridge collider contact in original logs. Mark PhysX/native `NOT_RUN` until a logged test really runs.

**Scope limits:** source-code `CHL003VehicleMotor.FixedUpdate` at the pinned HEAD applies `AddForce/AddTorque` whenever Running&&!Paused and velocity caps permit; does not query wheel-ground contact. Thus **airborne traction is source-visible P1 discrepancy**; should be fixed in existing CHL owner implementation after producer confirmation, *not* by B01-10. The source collision-telemetry counts alone **cannot tell grounded wheel vs chassis**. Need wheel-specific contact witness from B01-20.
