# CHL-003 interface and event ordering

State transitions: `Unconfigured → Ready → Running → Completed | Failed`. `Configure` requires 3–5 gates, exact nonzero actor identity token, nonnegative finite timeout (0 disables). `Begin` from Ready returns true once; duplicate begin no-op. `EnterCheckpoint(token,n)` accepts only when Running, unpaused, exact actor and n==CheckpointIndex, increments once and fires `CheckpointReached(newIndex)` exactly once. A collider on same vehicle cannot repeat an old checkpoint. `EnterFinish` accepts only after all gates; emits `Completed(elapsed)` exactly once. Unrelated collider never advances state. Fall or optional timeout emits `Failed(reason)` once. Time is monotonic and does not advance while paused. `Retry` returns to Ready resetting clock/last failure/indices/pause; controller additionally resets Rigidbody position/rotation and both velocities. `Cancel` reset has no success event. Caller must call `Begin()` after Retry.

Unity physical layer: `CHL003Gate` with BoxCollider.isTrigger and `OnTriggerEnter`; `CHL003CourseController.Configure(Rigidbody, CHL003Gate[], finish, spawn, failY, optionalTimeLimit)` checks references, distinct gates and type, binds owner. `Collider.attachedRigidbody == actor` is authoritative; not string name, collider child GUID, tag or gameplay ID. `Rigidbody` must be nonkinematic. `FixedUpdate` checks fail threshold; `Update` advances time. `CHL003VehicleMotor.Configure` uses AddForce/AddTorque and explicit axes. No persistence, rewards, base model imports or global input interception.

**Constraints:** Pure `CHL003CourseCore` has no Unity assemblies; source-tested using dotnet8. Unity adapter/scene/physics remain native NOT_RUN. No automatic MAPGEN route integration; external geometry MAY later supply ordered gate descriptors but core owns order/score. All game host integration is opt-in and owned by Codex after B01-00 G2.
