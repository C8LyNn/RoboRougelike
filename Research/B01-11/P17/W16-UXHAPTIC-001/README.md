# B01-11 PASS17/W16 — UXHAPTIC-001 R1: directional gamepad rumble decision gate

**Executable original .NET8 C# motor-feedback policy**, new and isolated: no real controller vibration is executed. It does not modify Codex Input System or any canonical `Assets/**`, VFX/audio, or frozen Secure Reattach #510 / Save schema #556. It is distinct from B01-11 UXCOMFORT #565 (visual flash/shake rate limiter), UXCAPTION #534 (auditory captions), and B01-12 A11Y-PREFS #479 (settings UI).

## Real functionality
`Runtime/HapticGate.cs` accepts **host-authoritative** `HapticEvent` with `RunId`, strictly increasing `Sequence`, nondecreasing `TimeMs`, typed `HapticKind`, directional `HapticSide`, and 0–100 intensity. Returns an **immutable** `HapticDecision` with `LeftPercent`, `RightPercent`, `DurationMs`, tier, disposition, whether a preceding impulse should be preempted, and a **`RequireVisibleCriticalAlert` invariant for current-run CriticalDamage** regardless of actual controller support/mute. No waveform, motor/Unity API, game input capture, rumble hardware tests, or medical claim.

- Priority: `CriticalDamage` is `Critical` (300ms duration, default cap 80); `PartDetached`/`Collision` are `Major` (160ms, cap 60); `WeaponImpact`/`Pickup` are `Minor` (80ms, cap 30). Side L/R uses a stronger channel on the event's side and 1/3 on the opposite. Center uses equal channels.
- During an active impulse, higher priority immediately preempts lower, returning `PreemptPrevious=true`; equal/lower is suppressed. Minor and unopposed Major share an exact **180ms cooldown**, Critical bypasses cooldown when free or interrupting lower tier. All suppression preserves monotonically consumed source sequence, no replay. Stale old run is ignored and does not request a spurious visual critical alert.
- `Strength=0` or a zero tier cap returns `SuppressedZero` and does not emit a pulse. `Enabled=false` returns `SuppressedDisabled`. `SetEnabled(false)` returns `true` exactly when a hardware adapter must **stop an active motor**, clears the active interval and preserves the played cooldown so rapid toggles cannot spam. New run clears transient pulse history but preserves enabled preference.
- Fail-closed validation for malformed future run IDs, duplicate/stale sequence, backward/negative clocks, invalid kinds and side, out-of-range strength, invalid configuration. Validated edge conditions close to `long.MaxValue` saturate end times to prevent overflow. This is a finite-state O(1) policy with no growing event history, tested under 1000-event bursts.

**Important:** The normal game HUD must always present danger independently from gamepad hardware. A real controller's rumble ability/motor limits must be checked in an authorized Unity Input System implementation by Codex; this source module cannot verify that. Haptics are optional, not a prerequisite to gameplay. Source-only and not integrated into the game.

## W17 — R2: mandatory physical motor stop at run boundary

A **source-level integration contract gap** was found in R1: `StartNewRun(nextRunId)` invalidated the internal active impulse and its 80/160/300ms interval but returned `void`. A future Unity Input System bridge could therefore still be vibrating a **previous run's gamepad motor** after the new run logically began, with no way for the transition caller to learn that motor shutdown was mandatory.

**R2 FIX:** `StartNewRun(nextRunId)` now returns a `bool`: `true` only when the outgoing run has a still-active, enabled motor request (`ActiveUntilMs > NowMs`). It **must be consumed by a future authorized host** to stop actual motors *before* publishing the new run. `false` for idle, expired, muted and zero-strength events. Invalid run IDs throw before state mutation. The method still clears active pulse, last-played cooldown, run sequence and clock, while retaining enabled setting. **All earlier source call sites invoking the method as a statement remain compatible.** This is NOT proof the game currently stops hardware: no Unity Input System adapter is installed. The return-value API is a source-compatible change only, not a binary-compatible ABI guarantee.
