## What it does
- Based on **real source inspection**: the current R1 IMGUI HUD at `Assets/R1/R1RunHUD.cs`, inspected historical source blob `049266e930fcb27062c0425dda248a970b681923` from gameplay commit `203a0805251ed28293888e43f2d49f0df63767c6`, uses a fixed 1280×720 virtual canvas and screen-scaled GUI matrix. This is a layout **proposal and executable implementation** to improve narrow/portrait and overscan UX, NOT a claim that this existing HUD has adopted it.
- `HudLayoutCore.Build(HudViewport)` yields immutable geometry in **top-left pixel coordinates**. Portrait and narrow displays use a critical-first stack, landscape >=980px safe width and sufficient aspect uses two columns. Mandatory **Critical, Vitals, Threats, Pause** remain present, safe-contained and non-overlapping. Optional objectives/tips are omitted if space is unavailable. Explicit `InvalidOperationException` if mandatory rects cannot fit, rather than silently clipping/overlapping.
- Accepts safe-area insets on all four edges, accommodates viewport 320×568 through 4K, user text scale 100/125/150% and deterministic pixel rounding. Layout has no screen/device queries, timer, network, input interception, save/gameplay changes or VFX.
- Strict checks on viewport dimensions 320–16384px width and 420–16384px height, insets and effective minimum safe area. `HudLayout.VisiblePanels()` returns an independent array, and `HudRect.Contains/Intersects` support easy layout QA.
- Exactly **75 executed original C# assertions per OS**, including eight specified resolutions ×3 user text scales, safe-area clipping, portrait/4:3/wide geometry, mandatory/optional visibility, font scale, invalid small viewports, overlap, deterministic outputs and negative input cases. ## W11 R2 — actual host-measured text height, fail-closed overflow repair
The R1 layout was deterministic and bounded but sized its text panels using fixed line-count budgets (2 critical, 4 vitals, 3 threats). Real localized/longer text or accessibility wrapping could require more vertical pixels than allocated. The new **original compiled C# functionality** is a second source-level `HudLayoutCore.Build(HudViewport,HudContentMetrics)` overload: host passes REAL inner-content pixel heights **after** its own font scaling and text wrapping, not guessed glyph widths or character counts. R2 grows essential panel rectangles as necessary, moves following panels/columns and suppresses optional objectives/tips if needed; throws `InvalidOperationException` if mandatory panels cannot fit, instead of silently clipping. The original R1 one-argument `Build(v)` is preserved unchanged in behavior, with zero metrics equivalent to baseline.
 
**Real security/robustness fix:** R1 `HudViewport` checked `left+right` and `top+bottom` using 32-bit addition. With `int.MaxValue` inputs these can wrap negative and bypass constructor bounds. R2 performs the sum as 64-bit `(long)` and rejects overflowed insets before layout. `HudContentMetrics` rejects negative or >16384px input measurements; no new dynamic allocation or gameplay mutations.
