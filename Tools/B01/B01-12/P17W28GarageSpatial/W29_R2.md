## Player-visible changes / source bugs fixed

1. **No hovered target**: R1 returned before rendering even the occupied red/blue/weapon/mechanism zones. R2 leaves mounted-vehicle zones visible in garage without showing any false candidate green permission. A candidate is drawn **only** when R3 actually has a hit.
2. **Large builds**: R1 added existing occupied and functional volumes before the candidate, and silently hit its 256-box cap. R2 reserves **four** boxes for the rotated 2x2 candidate footprint, keeping actual R3 `PlacementIssue` green/red feedback renderable even at 252 background boxes. Advisory functional volumes may still be capped; this is explicitly bounded.
3. **EditMode cleanup**: R1 called delayed `Destroy` for a temporary cube mesh in `Awake`; R2 uses `DestroyImmediate` outside PlayMode. Existing six real Unity tests + two new original NUnit tests explicitly address the EditMode cube and wide footprint reservation.
4. **Per-frame allocations**: replace per-frame child component array-returning `GetComponentsInChildren<T>` with Unity's reusable-list overload and scratch buffers. This removes those array allocations but is **not** a measured Player GC/performance result. W29's large-rig profiling still belongs to Unity QA.
