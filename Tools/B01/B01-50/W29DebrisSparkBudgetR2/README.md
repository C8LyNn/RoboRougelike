## Real W28 problem → corrected W29 code
Old W28 source is real runnable Unity MonoBehaviour bound to original **`R3Debris.Separated`** and existing **`DetachedModuleVfxController`**. However each observed detached part creates a VFX MonoBehaviour immediately, even if the budget only permits 16/70. On each quarter-second refresh it calls Unity `GetComponent<Rigidbody>()` for all tracked parts and writes `SetDetachedMotion(false, 0)` again to every unselected emitter. The game has a real 70-pieces/10-second R3Debris lifecycle; these unnecessary managed components and native engine calls can affect frame-time/GC when wreckage is dense. **This is source-level observed repeated work, NOT a measured native performance regression**.

**R2 actual production code change** in the SAME existing original Unity MonoBehaviour:
1. On actual `Separated`, register and cache the real physical `Rigidbody` ONCE; reject kinematic/nonexistent body as before. Keep existing `DetachedModuleVfxController` if present, but do NOT create a new component until a debris item receives a fastest-N visual lease.
2. At `RefreshNow`, use the cached real `Rigidbody.linearVelocity` for eligible debris, unchanged fastest-N pure production policy. Only when selected does `AddComponent<DetachedModuleVfxController>()` occur. Up to 16 new components for a normal 70-part encounter, rather than 70 eager components; later slower parts are still eligible for a lease when faster pieces disappear/slow down.
3. Revoke `SetDetachedMotion(false, 0)` ONLY after a previously enabled lease (skip repeated changes to ineligible nonemitters); keep selected per-frame speed update to preserve VFX001's actual rate.
4. `PurgeDead` keeps cached Rigidbody/emitter/last lease arrays aligned, stops only active visual lease, never touches or destroys original game body/Collider/part ID/Save. `OnDisable` stops active leases and unsubscribes exactly once. Duplicate controller still fails closed. Original 70 hard cap, config validation and 0..70 effect limit remain.
5. **Unity Original native PlayMode test SOURCE** upgraded from three to six cases. The existing two-bodies test now expects the slower part's VFX component to remain absent until selected. Adds 70 real `R3Debris`/eight component leases, late promotion after fast debris is retired, zero budget with no Rigidbody velocity changes. Native Unity NOT_RUN until real B01-60 operator.

**Safety caveat:** Existing prefab-provided VFX001 instances are treated as candidate emitters and disabled initially as before; no new VFX component is installed on an actively attached part. A detached piece observed after this optional controller is enabled is eligible; previously existing debris are not silently scanned. The controller is **not yet placed in an actual gameplay scene**; integration requires independent G0 and authorized native G1, never sneaky insertion.
