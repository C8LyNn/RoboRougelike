## Confirmed original-source safety defect and R2 implementation
**Prior immutable version:** [Draft PR #739](https://github.com/C8LyNn/RoboRougelike/pull/739) `d6d5526f5d8057f5a1f357218d460b808c307b5f`, original adapter Git blob `4cb010a5b9fa9f4f067b6bd90efdc9d1196548d2`. The original R1 Unity MonoBehaviour only resets its 8..600-step quiet eligibility on `OnCollisionEnter`/`OnCollisionExit`; it lacks `OnCollisionStay`. During prolonged physical contact, a low-speed cosmetic object can accumulate eight fixed samples despite receiving active collision-stay callbacks and request `Rigidbody.Sleep()` prematurely. A game dependency must NEVER be opted in; even detached cosmetic debris should fail closed under ambiguous ongoing contact.

**Corrected production R2:** adds an original Unity-facing `OnCollisionStay(Collision)` handler that resets the existing quiet policy only while `samplingActive && configured && !retired && enabled && allowCosmeticSleep && policy != null && collision != null`. Does not modify physics, velocities, transforms, mass, collision response or original policy; old original `DebrisSleepPolicy.cs` blob `6f407626639e68add97cd3d2e75c7d64a505fe6a` remains byte-identical. Null/stale disabled/unconsented Stay cannot reset current lease; sustained valid Stay prevents forced sleep. This deliberately means a resting body touching a static ground will receive no **extra** forced sleep while native Stay continues; Unity automatic sleep remains in control. Avoid installing R2 on any gameplay-critical Rigidbody even with this protection.

**No measured performance benefit:** Unity has built-in automatic Rigidbody sleep; this optional default-OFF component adds script cost. Only actual controlled licensed-Unity physics/Profiler before-vs-after comparison can justify enabling it. Source GREEN is not native PhysX or CPU optimization acceptance.
